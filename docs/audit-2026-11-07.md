# PluginPorter macOSアプリ包括監査 — 2026-11-07

> この文書は監査実施時点の記録です。以降の署名・公証・公開状況はREADMEとGitHub Releasesを参照してください。

確認できた9件の原因を修正し、ローカルのPluginPorter 1.2 build 5を作成した。元データを上書きするCLIの出力先指定、意図しないコピー、外部入力・バンドル読取境界、アーカイブの自己互換性、大容量検証のメモリー、Vitalの保存階層、ウインドウ再表示とキーボード操作を対象とした。公開済みbuild 4は更新していない。

### データ・権限・外部境界

- 設定はUserDefaultsの`PluginPorter.PresetLibraryRoots`（シンセ別ルートパス）。通常のBundle IDは`local.pluginporter.app`。Keychainへ資格情報を保存するコード、独自DB、独自永続キャッシュ、テレメトリー送信は確認されなかった。
- アーカイブは指定した`.pluginporter`フォルダの`manifest.json`と`payload/`。元パス・製品名・選択内容を含み、圧縮/暗号化されない。SHA-256は転送整合性であり、発行元の真正性署名ではない。xattr/権限等はハッシュ対象外という既存説明を維持。
- プリセットは選んだライブラリ内、復元はscopeごとのLibrary/Documents/Music/Shared内。stageは保存先の`.PluginPorter-*.partial`。異常強制終了時に残る可能性をREADMEが説明している。正常な失敗時のstage掃除はテストで確認したが、掃除自体が失敗する全条件は未確認。
- GUIの管理者操作は、700権限のランダム一時フォルダにplan/reportを置き、`/usr/bin/osascript`から自アプリのCLIを管理者として実行する。常設XPC/helper/LaunchDaemonはない。認証の実行・取り消し、rootでの所有者設定は今回は操作していない。
- 主にファイル読取/書込とシステム領域での管理者権限が必要。カメラ・マイク・画面収録・Accessibility・入力監視・Bluetooth・通知・ネットワークの要求コードはない。OSが保護するDocuments等は手動フォルダ選択でアクセスする構成。権限ダイアログの状態遷移は未確認。
- 直接配布とMac App Storeの条件を区別した。AppleはStoreではSandbox必須、Store外では推奨としている。[Appleの配布方式比較](https://developer.apple.com/macos/distribution)
- PrivacyInfo.xcprivacyは見つからず、UserDefaults利用はある。今回の直接配布物をApp Store提出と同一条件では判定しない。将来App Store提出/SDK追加時は使用理由と申告を再評価する。現時点で、当該直接配布に追加申告が必要かを全契約条件まで含めては判断できない。[Appleのrequired reason API説明](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api)

## D. 改善提案

以下は今回確認した不具合とは区別する。未測定の効果を保証しない。

1. **UI回帰と80%coverage目標**: PresetWindowの解析/再指定/保存/拒否と、busy中の終了をテスト可能な入力・状態へ分離する。全体coverageを継続計測する。カバレッジだけを上げるテストではなく、元データ保持・操作後状態を確認する。
2. **scanの欠落通知**: 現状は列挙/1製品の読み取り失敗を省略する。成功件数と読み取れなかった場所/件数を分けて返す設計にすると、不完全な一覧を判別しやすい。一般ユーザーへの表示と詳細ログの設計が必要。
3. **大量件数**: 重複パス検証と付属素材推定に反復走査がある。通常の使用量・目標時間を決めて測定し、必要なら索引/事前集計を導入。hashメモリー改善を一覧配列や全操作へ一般化しない。
4. **長時間処理**: cancel・処理ごとの詳細進捗・ログ上限と保存方針を設計。現在のbusy中の終了拒否はデータ保護の意図があり、無根拠に解除しない。
5. **配布診断**: commit/ビルド番号/ZIP hash/Mach-O UUID/dSYMを対応付けて保管。現行scriptにdSYM生成はなく、別保管の有無は不明。既存の署名・公証workflowは保持。
6. **ライセンス・プライバシー説明**: 外部SDKはないが、リポジトリ再配布の許諾条件を示すLICENSEファイルは見つからない。所有者が方針を決定する。法的適合性は断定しない。Store等へ配布範囲を変える場合はprivacy manifestと権限モデルを再評価する。
7. **小さな画面/アクセシビリティ**: minSizeが主950×780、整理1040×800のため、小さな有効表示領域や拡大設定での操作性を追加実機確認する。今回の画面では主要操作を実行できたが、全条件の評価ではない。
